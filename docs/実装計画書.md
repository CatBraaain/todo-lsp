GRAMMAR.md は冒頭で明記しています:

▎ Body text (TEXT) … End-of-line metadata (TAG) … These elements are extracted by the external scanner before parsing.

つまり TEXT/TAG の切り分けを scanner.c(external scanner) 側で行う のが仕様です。加えて tasks.todo に従い:

- corpus(test/corpus/\*.txt)が「正」。corpus は一切修正しない。
- scanner.c と grammar.js を修正し、tree-sitter test が全 corpus で合格するのをゴールとする。

コーパスから読み取った確定仕様（実装の真の仕様書）:

- task_line = (text)? (tag)\* … text は省略可（@done 単独 → text なし）
- heading_line = (text)? (colon) (tag)\* … : @done → text なし
- tag = (name) (arg)? … 両方 named node。@flag() の空 arg も (arg)
- TAG 開始条件: @ の直前が空白(または行頭)であること。これが user@example.com を TEXT 側に吸収する根拠（email me at user@example.com @done → text 内に @example.com
  を含む）。
- 末尾 colon 条件: : の後ろが「TAG ブロック(0個可)＋行末」のときだけ colon。time is 12:30 の : は TEXT の一部。

3. 設計（重要な技術判断）

判断: TEXT を external 化、TAG は grammar.js の構造ルール

TAG 全体を external token にすると 1 token = 名前付き子を持たない単一ノード になり、corpus が要求する (tag (name) (arg)) の内部構造を作れません。したがって:

- scanner.c: TEXT トークンを生成。その際「末尾 TAG ブロックの開始位置」と「末尾 colon」を認識し、TEXT の範囲をそこで打ち切る。結果として TEXT より後ろの @ だけが
  grammar.js の tag として解釈される（= TAG 認識の実質的な判断は scanner が担う）。
- grammar.js: tag = "@" name (arg)? を named 構造で定義。TEXT が user@example.com を吸収済みなので、文中の @ が tag に誤認されることはない。

これにより「TEXT/TAG の切り分けは scanner」「TAG の構造付与は grammar.js」という GRAMMAR.md 準拠かつ corpus 合致な分業になります。

TEXT 認識アルゴリズム（scanner.c の核心）

tree-sitter の lexer は 先読みしかできず位置の巻き戻しがない ため、以下の技法で1パス実現します:

- skip=false で文字を消費しながら進めつつ検証し、mark_end() で TEXT 終端を制御する。
- @(直前空白) に出会ったら、そこから行末まで「連続 TAG ブロック＋行末」か検証関数で消費判定。
  - 成立: mark_end(@の直前) を生かして TEXT 確定。残りは grammar.js の tag へ。
  - 不成立: 消費した文字も mark_end(現在位置) で TEXT に含めて続行。
- : も同様に「末尾 colon」検証で TEXT 終端または TEXT 巻き込みを切り分け。

5. フェーズ構成

Phase 1: grammar.js を corpus 準拠に再構築

- externals: [$.newline, $.indent, $.dedent, $.text] を追加
- extras: \r?\n を削除し NEWLINE external と整合させる（comment のみ残す、newline は各 line 末で消費）
- heading_line: seq(field("text", optional($.text)), $.colon, repeat($.tag), $.newline)
- task_line: seq(field("text", optional($.text)), repeat($.tag), $.newline)
- colon: () => ":"
- tag: seq("@", field("name", $.name), optional(field("arg", $.arg))) / name / arg を named rule 化

Phase 2: scanner.c に TEXT 認識を実装

- enum TokenType に TEXT 追加
- valid_symbols[TEXT] 時の分岐と、上記アルゴリズム（@/: 境界判定＋連続 TAG ブロック検証関数）を実装

Phase 3: NEWLINE/INDENT/DEDENT の調整

- NEWLINE を行末で生成し AST 非出現化（extras または inline で隠蔽）
- TEXT 追加に伴う valid_symbols の排他制御・error_recovery の整合

Phase 4: 検証（ゴール）

tree-sitter test # test/corpus/{block,edge,indent,tags}.txt 全合格
（※ tasks.todo の方針により、実行確認は最終ゴール時のみ。corpus は修正しない。）
